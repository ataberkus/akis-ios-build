# mobile/

Yuva for iOS: a thin [Capacitor](https://capacitorjs.com) shell that opens the live site, `https://yuva.chat`, in a
WKWebView, as the desktop shells do. The plan and the open questions are in `docs/mobile-plan.md`.

- `capacitor.config.json`: bundle ID `chat.yuva.app`, `server.url` (the site), `appendUserAgent: YuvaApp/iOS`: the
  site reports the app as its own client kind, `mobile` ("Mobil uygulama" on profiles; `clientReport` in
  `src/lib/yuva/desktop.ts`), `server.errorPath`: `www/offline.html`, shown when the site can't be loaded; it retries
  every 15 s, when the phone comes back online and on "Tekrar dene".
- `ios/App`: the Xcode project (Swift Package Manager, no CocoaPods). `ios/App/App/public` and
  `ios/App/App/capacitor.config.json` are generated by `npx cap sync ios` and not committed.
- Native parts (`ios/App/App`):
  - `YuvaMobilePlugin.swift`: `window.yuvaMobile` on the site's own pages (a user script over Capacitor's bridge;
    the site's side is `src/lib/yuva/mobile-app.ts`): push registration (APNs token, stored by
    `saveNativePushToken`), the app icon's badge (the unread count), local notifications while the app runs in the
    background, and notification taps (`url` is loaded, or handed to the page when it is already in the app).
  - `YuvaCall.swift`: the voice room as an outgoing CallKit call (lock screen, Dynamic Island, the green pill) with
    mute and end, driven by `useVoiceMediaSession` (`src/lib/yuva/mobile-voice.ts`). `localStorage["yuva:callkit"] =
    "0"` in the app switches it off to compare. CallKit isn't allowed in China: leave that App Store storefront out.
  - Mic and camera permission texts, background audio (`UIBackgroundModes: audio`, a `playAndRecord` session in
    `AppDelegate.swift`), `App.entitlements` (`aps-environment`: development for Debug, production for Release).
- Push: the server sends them through APNs (`src/lib/yuva/push.server.ts`, `apns.server.ts`), composing the text the
  service worker would show (`native-push.ts`). Needs an APNs key on the server (`APNS_*` in
  `deploy/yuva.env.example`); without it the app gets no pushes and everything else works.
- Icon and launch image: `ios/App/App/Assets.xcassets`, made from `desktop-mac/assets/icon-1024.png` (iOS wants a
  full-bleed square without transparency; the system rounds the corners).

## Build

On a Mac with Xcode: `cd mobile && npm ci && npx cap sync ios && npx cap open ios`.

CI: `ios.yml` in `ataberkus/yuva-desktop-build` builds it on a macOS runner, launches it in the simulator and uploads
it to TestFlight, signed by hand with the Apple Developer team, distribution certificate and App Store Connect API key
Akış uses (setup steps at the top of the workflow). `scripts/testflight.mjs` registers the App ID, keeps the App Store
profile "Yuva App Store" and picks the build number: one above App Store Connect's highest for `version` in
`package.json` (a new version starts at 1). Bump `version` for a new release.

```
gh workflow run ios.yml -R ataberkus/yuva-desktop-build -f ref=main -f testflight=true
```
